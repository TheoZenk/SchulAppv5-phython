Einwilligungserklärung zur Nutzung digitaler Werkzeuge im P-Seminar

Dientzenhofer Gymnasium Bamberg
P-Seminar Informatik, Jahrgangsstufe 11 (Herr Löffler)
Schuljahr 2026/2027

Betreff: Einwilligung in die Nutzung von VS Code, Codeberg, GitHub Copilot und GitHub Codespaces im P-Seminar „Entwicklung einer App mit Python/Flet"

Liebe Erziehungsberechtigte, liebe Schülerin, lieber Schüler,

im P-Seminar entwickeln die Schülerinnen und Schüler gemeinsam eine App in der Programmiersprache Python (mit der Bibliothek Flet, die auf dem UI-Framework Flutter aufbaut). Sie arbeiten dabei wie ein echtes kleines Entwicklerteam: mit dem Editor VS Code auf dem eigenen Laptop, der Versionsverwaltung Git und einem gemeinsamen, zentralen Code-Repository auf Codeberg.org. Zusätzlich soll die KI-gestützte Programmierunterstützung GitHub Copilot genutzt werden, die für Schülerinnen und Schüler über den Bildungszugang von GitHub kostenlos ist. Schülerinnen und Schüler, die über keinen eigenen Laptop oder MacBook verfügen, können vollständig über den Browser mit GitHub Codespaces (einer Entwicklungsumgebung in der Cloud) am Seminar teilnehmen — ein Schulrechner mit Internetbrowser genügt.

Damit die Werkzeuge eingerichtet und genutzt werden dürfen, ist — vor allem wegen der Anbieter mit Sitz in den USA — eine Einwilligung erforderlich bzw. empfehlenswert. Dieses Schreiben erläutert Ihnen die einzelnen Werkzeuge, die dabei verarbeiteten Daten und Ihre Rechte. Die Einwilligungen können je Werkzeug einzeln erteilt oder abgelehnt werden.



1. Worum geht es im Seminar (Kurzüberblick)





Ziel: Gemeinsame Entwicklung einer App über die Dauer des P-Seminars; das Projekt ist Teil der Seminarleistung.



Team: Vier Schülerinnen und Schüler plus betreuende Lehrkraft.



Technologie: Python mit der Bibliothek Flet (Grafikoberflächen auf Basis von Flutter).



Arbeitsweise: Versionsverwaltung mit Git; jeder trägt über ein eigenes Konto Änderungen am gemeinsamen Code bei. Die KI-Unterstützung (Copilot) liefert Vorschläge beim Tippen und kann Fragen zum Code beantworten — sie ersetzt nicht das eigene Verständnis, sondern unterstützt wie ein „Copilot" neben dem Entwickler.



2. Die einzelnen Werkzeuge

2.1 Visual Studio Code (VS Code) — lokal auf dem eigenen Laptop





Was es ist: Ein frei verfügbarer Programmier-Editor von Microsoft, in dem der Quellcode geschrieben, ausgeführt und mit Git verwaltet wird.



Wo er läuft: Die Software wird lokal auf dem eigenen Laptop installiert. Der geschriebene Code bleibt zunächst auf dem eigenen Gerät; ein Microsoft-Konto ist für die Nutzung nicht erforderlich.



Datenverarbeitung: VS Code sendet standardmäßig technische Telemetriedaten (z. B. Nutzungsstatistiken, Absturzberichte) an Microsoft (Sitz: USA). Diese Übertragung lässt sich in den Einstellungen deaktivieren — was im Seminar gemeinsam durchgeführt wird. Werden Erweiterungen (z. B. Python-Support, Git-Integration) installiert, werden dafür Anfragen an Microsoft-Server übertragen.



Notwendigkeit: Diese Einwilligung ist für die Teilnahme am Seminar erforderlich, sofern ein eigener Laptop vorhanden ist. (Alternative bei eigenem Laptop wäre z. B. die Open-Source-Variante VSCodium ohne Telemetrie, die aber nicht mit Copilot kompatibel ist.)

2.2 Codeberg.org — zentrales, gemeinsames Code-Repository





Was es ist: Eine Plattform für die Verwaltung von Quellcode („Repository"), vergleichbar mit GitHub, betrieben vom Codeberg e.V., einem gemeinnützigen Verein in Deutschland. Die Server stehen in Deutschland; es gibt keine kommerzielle Verwertung der Inhalte, keine Werbung und kein Tracking durch Dritte. Die Zusammenarbeit (wer hat wann welchen Beitrag geleistet) bleibt dauerhaft nachvollziehbar — wie in professioneller Softwareentwicklung üblich.



Was dafür nötig ist: Jede Schülerin/jeder Schüler legt ein eigenes Konto an.



Datenschutzfreundliche Regeln im Seminar: Es werden ausdrücklich Pseudonyme als Benutzernamen und projektspezifische E-Mail-Adressen (nicht die private E-Mail-Adresse) verwendet. Nichts am Code ist nicht personenbezogen; es sind keine Klarnamen oder sonstigen personenbezogenen Daten auf dem Profil sichtbar.



Notwendigkeit: Diese Einwilligung ist für die Teilnahme am Seminar erforderlich — das Repository ist die zentrale Grundlage der Projektarbeit.

2.3 GitHub-Konto und GitHub Copilot (Bildungszugang) — KI-gestützte Programmierunterstützung





Was es ist: GitHub Copilot ist ein KI-Assistent, der direkt im Editor Code-Vorschläge macht, Code erklärt, Fragen beantwortet und beim Testen unterstützt. GitHub (ein Unternehmen von Microsoft, Sitz: USA) stellt Schülerinnen und Schülern den Zugang über das Bildungsprogramm GitHub Education kostenlos bereit. Mindestalter für ein GitHub-Konto: 13 Jahre.



Wie der kostenlose Zugang funktioniert: Jede Schülerin/jeder Schüler legt ein eigenes GitHub-Konto an und verifiziert den Schülernachweis über GitHub Education (dabei wird ein Nachweis der Schule bzw. die Schul-E-Mail-Adresse verwendet; die Verifizierung kann über die betreuende Lehrkraft organisiert werden).



Datenverarbeitung: Zur Erzeugung der Vorschläge werden Ausschnitte des aktuellen Codes und die Eingaben an Server von GitHub übertragen (Standard-Hosting in den USA). Die Übermittlung in die USA erfolgt über den EU-US Data Privacy Framework; GitHub bietet eine Datenschutzvereinbarung an, die die Einhaltung der DSGVO zusagt.



Wichtige Einstellung im Seminar: Copilot kann die Daten standardmäßig zum Training seiner KI-Modelle verwenden. Diese Nutzung wird in den Kontoeinstellungen deaktiviert („Allow GitHub to use my data for AI model training" → aus) — ebenfalls gemeinsam im Seminar eingerichtet. Nach Angaben von GitHub werden die übertragenen Daten ohne diese Freigabe nicht zum Modelltraining verwendet.



Umgang mit Inhalten: In die Repositorys und in Copilot gehören nur projektbezogene, nicht-personenbezogene Inhalte — keine Klarnamen von Personen, keine privaten Daten, keine schulischen Leistungsdaten.



Notwendigkeit: Diese Einwilligung ist freiwillig. Ohne sie kann die Schülerin/der Schüler weiterhin voll am Seminar teilnehmen; die KI-Unterstützung entfällt, der Arbeitsaufwand steigt ggf. etwas.

2.4 GitHub Codespaces — Entwicklungsumgebung im Browser (nur bei Bedarf)





Was es ist: Eine vollständige Entwicklungsumgebung (Editor + vorkonfigurierter Rechner in der Cloud, „virtuelle Maschine"), die im Browser läuft — auch von einem Schulrechner aus. Sie ist für Schülerinnen und Schüler über GitHub Education ebenfalls kostenlos nutzbar (mit monatlichem Nutzungskontingent, das für das Seminar ausreicht).



Für wen: Nur für Schülerinnen und Schüler, die keinen eigenen Laptop/MacBook mitbringen können oder wollen. Wer einen eigenen Laptop hat, braucht Codespaces nicht.



Datenverarbeitung: Im Codespace werden die Projektdateien sowie Nutzungsdaten (Laufzeit der Umgebung, IP-Adresse, Konto) bei GitHub (USA) verarbeitet. Es fallen dieselben Datenschutzhinweise wie unter 2.3 an. Am Ende jeder Einheit kann der Codespace gestoppt werden; die Daten verbleiben beim GitHub-Konto, nicht auf dem Schulrechner.



Notwendigkeit: Diese Einwilligung ist nur relevant und freiwillig; sie wird nur benötigt, wenn die Umgebung tatsächlich genutzt werden soll.



3. Datenschutz im Überblick





Grundsatz: Es werden keine Noten, Leistungsdaten oder sonstigen schulischen personenbezogenen Daten an die genannten Anbieter übermittelt. Die Bewertung des Seminars durch die Schule ist von der Kontonutzung unabhängig.



Pseudonymisierung: GitHub- und Codeberg-Konten werden mit Pseudonymen und projektspezifischen E-Mail-Adressen betrieben (siehe 2.2 und 2.3).



Drittlandübermittlung: Microsoft/GitHub verarbeiten Daten in den USA; die Übermittlung stützt sich auf den EU-US Data Privacy Framework und die Datenschutzvereinbarungen von GitHub. Codeberg verarbeitet als deutscher Verein die Daten in Deutschland.



Rechtsgrundlage: Die Einwilligungen beruhen auf Art. 6 Abs. 1 lit. a DSGVO. Für Schülerinnen und Schüler unter 16 Jahren ist zusätzlich die Zustimmung der Erziehungsberechtigten erforderlich (Art. 8 DSGVO); bei Vollendung des 16. Lebensjahres können die Schülerinnen und Schüler selbst einwilligen.



Widerruf: Jede Einwilligung kann jederzeit, formlos und ohne Nachteile widerrufen werden (z. B. per E-Mail an die unten genannte Adresse). Accounts und zugehörige Daten werden dann gelöscht bzw. deaktiviert.



Daten minimieren: Nur projektbezogene Inhalte einstellen; keine privaten Fotos, Adressen oder personenbezogenen Daten Dritter im Code oder in Profilen.



Keine Nachteile bei Ablehnung: Eine Ablehnung (auch der optionalen Einwilligungen) hat keinerlei Nachteile für die Bewertung oder die Teilnahme am Seminar. Es werden alternative, datenschutzfreundliche Werkzeuge bereitgestellt.
